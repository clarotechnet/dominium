## Cloudflare VPC Service — porta fixa (bloqueio validado em 30/10/2026)

A configuração existente usa VPC Services com IDs próprios. Segundo a Cloudflare, a porta do serviço VPC é fixa e prevalece sobre a porta escrita na URL fetch. IMPORT_SERVICE (serviço existente) não encaminha para 9342 apenas porque a URL mudou.

A correção cria um binding independente BACKLOG_SERVICE para um serviço VPC com origem 127.0.0.1 porta 9342. Worker de laboratório já usa exclusivamente BACKLOG_SERVICE para as rotas de Backlog; quando esse binding não existe, responde HTTP 503 sem tocar na conexão 8765.

Wrangler no PC do trabalho está autenticado na conta 416ec837ec86eec81dcc8dcade3d32ae, mas a conta não lista os serviços usados na configuração DOMINIUM; consultar ID antigo retorna 5104. **Não criar/deploy na conta errada.**

Para publicar: autenticar Wrangler na conta realmente proprietária do Cloudflare Worker, localizar ID do Cloudflare Tunnel associado aos VPC Services ativos, criar um terceiro serviço VPC com host loopback e HTTP port 9342, adicionar o novo service_id como BACKLOG_SERVICE em wrangler.jsonc, validar Worker em dry-run + GET autenticado e preparar rollback. Não alterar os IDs IMPORT_SERVICE/DESC_SERVICE. Nenhuma dessas operações foi feita em produção.

O Sidecar está instalado e foi testado apenas localmente no servidor. Carga anual segue bloqueada (HTTP 423). Banco D1 antigo não é usado pela integração nova.
